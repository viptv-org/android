# Scoped Android TV development enablement

The owner's 2026-10-07 instruction, “the tv is online now, native should be
enabled”, authorizes a narrow experimental development installation on the
configured TV. The owner's subsequent explicit request to enable native on the
shared development TV emulator authorizes the same narrow experimental scope
for that emulator and its paired account/session. It does not declare the general native contract qualified or
authorize global production admission. The original design contract remains
unchanged. In particular, arbitrary stalled synchronous OS IO has no proven
unconditional two-second settlement bound; failed settlement stays failed,
retains work/cache reservations and quarantines the manager. This installation
accepts that known experimental limitation without declaring NT-04 passed.

The normal application's private `nativeTorrentScopedQualification` Gradle
property names an ignored JSON receipt. Without the property there is no
enabling asset. Release builds and isolated fixture builds refuse the property.
The receipt must record actual normal Android JNI and owned Media3 PASS results,
the sealed normal APK/evidence hashes, the exact committed Android source,
normal gateway/core/design pins and lock/library hashes, and the configured
Android TV model, API and process ABI. The closed target list contains the
configured AFTLAS01/API 30/ARMv7 TV and the shared
sdk_google_atv64_x86_64/API 36/x86_64 TV emulator. Each receipt admits exactly
one tuple and requires its own actual evidence; evidence from one target does
not qualify the other. The build refuses stale executable inputs. Modified
owner guides are preserved and listed as `documentationOnlyChanges` in the
emitted asset; this exception cannot admit code, artifact or pin changes.
The runtime checks its actual model/API/process ABI, TV platform, normal APK
library hashes, facade initialization and suspend-aware clock. A cache owner
must also initialize successfully and remain available before advertisement.
Any failed fact leaves native unavailable. Other target tuples and ordinary
unqualified builds continue to omit native fields.

The qualifying normal APK uses normal public DHT/TCP gateway artifacts,
app-private storage and system trust. No fixture owner, private peer selector,
fixture certificate or additional user setting is introduced. Owned-private
Media3 evidence qualifies that measured pipeline only; it does not establish
sustained public-peer/resource, audible human, remote or distribution acceptance.
The final enabled APK needs its own hash, normal isolation verification and
runtime check in the ignored evidence record; a donor APK hash does not identify
the installed enabled APK.

Backend operator configuration is `VIPTV_NATIVE_TORRENT_SCOPED_POLICY`, absent
by default. Its closed JSON schema requires:

- `decision`: `scoped_experimental_sticky_quarantine_v1`.
- `account_id`: the configured authorized account's positive database ID.
- `device_session_id`: the exact configured TV's stable paired-session family.
- `platform`: `android_tv`.
- `max_active_grants`: one or two; two permits outgoing playback plus one
  prepared candidate.

The backend requires the paired-device principal and exact account/session
match. Device names are insufficient identity evidence. Native negotiation,
source/index proof, grants, limits, request tombstones and retirement remain
mandatory. Unsupported clients, direct HTTP, ordinary gateway delivery and live
behavior retain their existing contracts. Real IDs and environment configuration
belong only in the owner's ignored development runbook; no production service
is activated by this source change.

Activate only after the selected target's actual JNI/owned Media3 checks pass and
the exact device session is established from its current authorized credentials.
Build the receipt-bearing normal debug APK, verify its normal libraries/trust
and qualification asset, and install with the existing signing identity while
preserving data, sign-in and origin. Apply the scoped operator JSON only to the
authorized development service using its private preflight/rollback record.
Verify the actual running backend artifact and an authenticated scoped native
start; protocol support alone proves no admission. Report public-network and
physical/human results separately.

For the shared emulator, run fixture acquisition and Media3 checks on a separate
owned QA TV emulator with the same measured tuple. Never install fixture trust,
reset data, change backend or run destructive qualification on the shared
serve-avd instance. Validate the normal enabling gate on the shared instance
after its state-preserving install. Backend admission remains bound to the
shared instance's exact paired-session family; an emulator model is not an
authorization identity.

Rollback removes the scoped backend configuration and installs the previously
sealed disabled normal APK with the same signing identity and retained data.
Stop Media3, retire pending/active native control, join acquisition/cache work
and release/tombstone requests before restoring scope. Failed settlement must
retain quarantine/accounting. Disabling advertisement alone does not retire a
grant; no automatic source substitution is authorized. Restore the recorded
development executable/service configuration without deleting database volumes.
